# Research result

## Material Claims

- [C1][material][evidence][supported] GitHub Copilot CLI documents COPILOT_HOME as replacing the entire ~/.copilot directory (settings, session history, etc.), with COPILOT_CACHE_HOME separate and unaffected by COPILOT_HOME. [S1]
- [C2][material][evidence][supported] GitHub Copilot CLI treats --config-dir as a legacy option, prefers COPILOT_HOME, and lookup order is --config-dir, then COPILOT_HOME, then ~/.copilot; older XDG-based locations are migrated to ~/.copilot at startup when COPILOT_HOME is unset. [S1]
- [C3][material][evidence][supported] Block goose documents GOOSE_PATH_ROOT as overriding the root for all goose data, config and state, creating config/, data/ and state/ subdirectories under it. [S2]
- [C4][material][evidence][supported] Google Gemini CLI configuration reference documents GEMINI_CLI_HOME as the root for user-level configuration and storage, with a .gemini folder created inside it; the part of the page read (first 100000 of 116753 characters) has no XDG text. [S3]
- [C5][material][evidence][supported] OpenCode config page documents OPENCODE_CONFIG_DIR as an extra config directory loaded after the global config and .opencode directories so it can override them (it adds to rather than replaces the global ~/.config/opencode), and the page does not mention XDG. [S4]
- [C6][material][evidence][supported] GitHub Copilot CLI documents COPILOT_HOME as relocating its user-level instruction locations away from $HOME/.copilot, and COPILOT_CUSTOM_INSTRUCTIONS_DIRS as a comma-separated list of extra directories holding AGENTS.md and *.instructions.md. [S5]
- [C7][material][evidence][supported] Codex CLI reads its global instruction file from the Codex home directory (default ~/.codex, relocatable with CODEX_HOME), taking AGENTS.override.md if present else AGENTS.md, using only the first non-empty file at that level. [S6]
- [C8][material][evidence][supported] Codex CLI walks from project root down to cwd, checks AGENTS.override.md, AGENTS.md, then project_doc_fallback_filenames in each directory (one file per directory), and concatenates root-down so nearer files appear later (merged, nearest last, 32 KiB default cap via project_doc_max_bytes). [S6]
- [C9][material][evidence][supported] Claude Code (v2.1.277+) reads AGENTS.md natively only as a fallback when no CLAUDE.md, .claude/CLAUDE.md or CLAUDE.local.md exists in or above the working directory (default setting claude-md-or-agents-md); ~/.claude/CLAUDE.md is the user-level file and does not suppress the AGENTS.md fallback; AGENTS.override.md and .agents/ are not read; all files are concatenated, nearest last. [S7]
- [C10][material][evidence][supported] OpenCode's documented global instruction file is ~/.config/opencode/AGENTS.md (XDG-style), with ~/.claude/CLAUDE.md as a fallback unless OPENCODE_DISABLE_CLAUDE_CODE(_PROMPT) is set; within each category the first match wins (AGENTS.md over CLAUDE.md), and instruction files from the opencode.json instructions array are combined with AGENTS.md files. [S8]
- [C11][material][evidence][supported] OpenAI Codex documents a user-scope skills directory at $HOME/.agents/skills, repo-scope .agents/skills from cwd up to the repo root, an admin scope at /etc/codex/skills, and explicitly supports symlinked skill folders. [S9]
- [C12][material][evidence][supported] Gemini CLI documents ~/.agents/skills/ as a user-tier alias for ~/.gemini/skills/ and .agents/skills/ as a workspace alias for .gemini/skills/, with the .agents alias taking precedence within the same tier; the page does not mention symlinks. [S10]
- [C13][material][evidence][supported] GitHub Copilot CLI documents project skills in .github/skills, .claude/skills or .agents/skills and personal skills in ~/.copilot/skills or ~/.agents/skills; the page does not mention symlinks, COPILOT_HOME or environment variables. [S11]
- [C14][material][evidence][supported] A Google codelab states Antigravity CLI does not read ~/.agents/skills (which Antigravity IDE does) and uses ~/.gemini/antigravity-cli/skills globally, while also listing ~/.gemini/config/skills/ as global scope in another section; it is undated and a tutorial, not product reference. [S12]
- [C15][material][evidence][supported] The Agent Skills format was originally developed by Anthropic and released as an open standard; agentskills.io lists adopters including Claude Code, Codex, Gemini CLI, OpenCode, GitHub Copilot, Cursor and Goose, and states no spec version on the overview page or the GitHub repo page. [S13]
- [C16][material][evidence][supported] GitHub Copilot CLI documents COPILOT_HOME as an environment variable that replaces the entire ~/.copilot configuration directory (which holds user-level mcp-config.json), and says previous XDG-based locations are migrated to ~/.copilot at startup when COPILOT_HOME is not set. [S1]
- [C17][material][evidence][supported] Claude Code documents local-scope and user-scope MCP servers as stored in ~/.claude.json and project-scope servers in .mcp.json at the project root; the MCP page fetched states these paths without describing any relocation of ~/.claude.json. [S14]
- [C18][material][evidence][supported] Claude Code's MCP page names CLAUDE_CONFIG_DIR as the configuration directory (default ~/.claude) used for user-scope and managed MCP dynamic-header helpers, but the portion of the env-vars page read did not include the CLAUDE_CONFIG_DIR row, so whether it relocates ~/.claude.json is not established here. [S14]
- [C19][material][evidence][supported] OpenAI Codex stores MCP servers as [mcp_servers.<name>] tables in ~/.codex/config.toml or a trusted project's .codex/config.toml, and the same configuration is shared by the ChatGPT desktop app, Codex CLI and IDE extension; the page read does not mention CODEX_HOME. The old developers.openai.com/codex/mcp URL now returns a 308 redirect to learn.chatgpt.com. [S15]

- [C50][material][evidence][supported] The Agent Skills specification defines a skill as a directory containing at minimum a SKILL.md file with YAML frontmatter; name (1-64 chars, lowercase alphanumerics and hyphens, must match the parent directory name) and description (1-1024 chars) are required, while license, compatibility, metadata and allowed-tools (experimental) are optional. It specifies no user-level or home-directory discovery path and no relocation mechanism. [S41]

## Unknowns

- OpenCode skills page: the six skill locations are located by every verifier, but the claim also asserted OPENCODE_DISABLE_CLAUDE_CODE_SKILLS, which that page does not mention (it is documented on the CLI reference); the compound claim was held back rather than split after the fact.
- Codex CLI: no verified claim on where session state lives under CODEX_HOME.
- Antigravity: sessions and brain-state location and relocation are not documented in anything read; the IDE's own paths are unverified; whether agy honours a skills.json entry for ~/.agents/skills versus the documented antigravity-cli/skills directory is open.
- Gemini.app and Muse.app: no vendor documentation was read for either application's state under ~/Library/Application Support.
- xAI Grok Build: it is documented ($GROK_HOME, ~/.grok) but whether GROK_HOME also moves ~/.grok/sessions is not stated; no verified claim on its MCP or skills paths.
- Cursor: whether CURSOR_CONFIG_DIR affects mcp.json, skills or IDE state is not documented in the pages read; chat and session-state location and --user-data-dir are undocumented there.
- goose: the config and hints pages do not say whether GOOSE_PATH_ROOT covers ~/.config/goose (config.yaml, .goosehints, AGENTS.md); session location is unverified.
- Claude Code: the documentation read does not state whether CLAUDE_CONFIG_DIR carries .claude.json, nor where user skills, commands and agents live under it.
- Gemini CLI: its MCP configuration path under GEMINI_CLI_HOME and whether the global GEMINI.md resolves under it are not stated in the pages read.
- Standards: the MCP specification version and steward, and the Agent Skills steward and governance, are not established by any verified claim; A2A and ACP relation beyond ACP's Zed/JetBrains interim governance is unverified.

## Novel Actionable Findings

- GitHub Copilot CLI documents COPILOT_HOME as a supported way to replace the whole ~/.copilot directory (COPILOT_CACHE_HOME separately); exporting it in the launch environment would make the ~/.copilot symlink optional. Verify with one session before relying on it. (basis: C1, C2, C16)
- Gemini CLI reads its home from GEMINI_CLI_HOME and a context file name from context.fileName; including AGENTS.md there lets one shared AGENTS.md be read through a supported setting. (basis: C4, C34)
- Antigravity CLI documents no relocation variable and keeps every documented global path under ~/.gemini; keep the ~/.gemini doorway and re-verify after each agy upgrade. (basis: C31, C32, C33)
- ~/.agents/skills is the documented user-level skills path for Codex, Gemini CLI, Copilot CLI, Cursor and goose; skills that exist only in another root are invisible to those vendors. (basis: C11, C12, C13, C36, C47)
- Do not build the runtime root on XDG variables: Codex and Gemini CLI closed XDG requests as not planned, and Claude Code does not read XDG_CONFIG_HOME. (basis: C28, C29, C46)
- Claude Code's supported relocation is CLAUDE_CONFIG_DIR, which moves the whole config and data directory; compatibility readers such as Cursor and goose still read ~/.claude/skills. (basis: C46, C36, C47)
- OpenCode documents config-directory variables but no data-directory variable; the PR that proposed data, cache, log and state variables was closed unmerged, so do not adopt those names. (basis: C43, C44, C45)
- goose documents GOOSE_PATH_ROOT as moving all config, data and state; verify whether that also covers ~/.config/goose/.goosehints before relying on it. (basis: C3, C49)
- Cursor's CURSOR_CONFIG_DIR is documented for the CLI config file only; mcp.json and skills stay under ~/.cursor, and User Rules are not file-backed. (basis: C35, C36, C37, C38)
