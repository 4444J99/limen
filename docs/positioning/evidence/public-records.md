# UCC Public-Records Intelligence Platform — Public Evidence Packet

## Bounded claim

The public-records platform demonstrates a multi-stage public-record decision pipeline. Four
implemented state collectors (CA, TX, FL, and NY) sit on a broader architecture. It does not claim
fifty-state deployment, complete coverage, buyer adoption, or commercial outcomes.

- Architecture and implementation: [public source](https://github.com/organvm-iii-ergon/public-record-data-scrapper).
- Exact-head verification: [successful workflow run](https://github.com/organvm-iii-ergon/public-record-data-scrapper/actions/runs/31310353594)
  at `139fa7b40d875ecfe3a8c693dedfab46671739fd`.
- Public deployment: [live product surface](https://organvm-iii-ergon.github.io/public-record-data-scrapper/).

## Metric treatment

The count of four is a repository-asserted implementation count with a public source and deployment
anchor. It is deliberately not restated as a fifty-state live-coverage count. Reproduce the source
and required collector terms with `python3 scripts/flagship-evidence.py --verify-live --json`.

## Authorship and limitations

Public implementation and deployment are the evidence boundary; no private sources are needed for
this packet.

- Four implemented collectors do not establish fifty-state deployment or adoption.
- The landing page is an implementation anchor, not a claim about data completeness or commercial use.

## Withdrawal route

If the source no longer supports the four-collector wording or the deployment stops validating,
withhold the metric and use the non-numeric architecture description until refreshed evidence is
reviewed.
