# Prompt sequence study

Owner: [#3056](https://github.com/4444J99/limen/issues/3056).
Publication: [draft #3087](https://github.com/4444J99/limen/pull/3087).

The current proposal is [vocabulary-v4.json](vocabulary-v4.json): **19 operator operations**.
It is research evidence, not an installed command pack. The goal remains active.

| Purpose | Proposed operations |
|---|---|
| Advance or reshape authorized work | continue, plan, fix, correct |
| Resolve context and orientation | status, next, explain, recall, context |
| Assess evidence | review, verify |
| Bind a decision | approve, choose |
| Publish, apply and prove session release | ship, apply, closeout |
| Transfer work, observe it or persist a lesson | handoff, watch, codify |

Each operation retains its target, payload, authority, constraints and completion evidence.
A common operation can have different outputs as those inputs change. Supplying new information
cannot be shortened to a bare verb without retaining that information or its immutable reference.

## Review the evidence

- [Native readback and provenance correction](native-readback-v1.md): three native main-thread
  views agree with all 27 captured bodies and turn bindings. Six captured inputs are identified
  managed recovery probes and are excluded from the operator-intent count.
- [Longer-sequence comparison](long-sequence-review-v1.md): all 24 post-first positions in those
  three captures are analyzed in context. Read it with the later provenance correction.
- [Frozen substitution review](substitution-review-v1.json): 27 follow-ups from nine held-out
  source files assessed against v2 by one coder; not an independent or runtime test.
- [Original contextual review](native-sequence-review.json): earlier source-bound candidates
  with incomplete-body limitations retained.
- [Source-attribution revision](study-v3.md): native-turn association, derived frames and the
  broader bounded native extraction.
- [Native readback receipt](native-readback-evidence-v1.json): current-view counts, source
  comparisons, managed-input provenance and explicit nonclaims.

The existing private native-catalog.html places whole captured sequences in columns and keeps
every retained prompt in order. Search selects complete columns. It contains 382 displayed file
sequences and 3,500 prompt rows; it remains a frozen earlier rendering. Its candidate glossary
does not yet contain v4. Private binding files identify the U aliases used in the newer review.

The source-level review accounts for 102 post-first positions across 23 files, with six now
identified as managed inputs. The other 96 are candidate operator-context positions, including
remaining retention and attribution limitations. This is not a corpus substitution percentage.

## Version and acceptance boundaries

V2 remains the frozen evaluation baseline. V3 proposed an exact-response operator based on six
then-unattributed probe inputs. V4 preserves that research history but excludes the operation
from the primary vocabulary after those inputs were bound to managed recovery records.

Native main-thread pagination is not proof of complete side conversations. One reviewed chat's
earlier recovery used Computer History observations; the original side-turn objects and replies
are still missing. User-item identifiers also differ between native views, so source namespaces,
verified turn bindings and exact ordered text must accompany joins.

The full finish line remains open: reconcile unresolved native sources and logical lineage,
complete contextual corpus coding, validate substitutions independently, and finish the owning
source-repair and publication requirements. Catalog regeneration and the full gate remain
subject to host admission. Historical replies, local tests, publication, merge, deployment and
session release are separate evidence claims.
