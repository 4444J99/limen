Owner: [#3056](https://github.com/4444J99/limen/issues/3056). Publication: [draft #3087](https://github.com/4444J99/limen/pull/3087).

This review reads **47 retained source positions and 38 follow-ups** across nine entire captured files. All 47 input bodies exactly match the stored native records. None has `record.metadata.retained_source`; that absence proves neither truncation nor complete earlier history. All nine snapshots match their captured hashes and reached file EOF. [The ordered cases and source evidence](unknown-retention-review-v1.json) preserve each prompt/reply reference, required binding and limitation. These are same-coder candidates, not independent substitutions or an operator-origin count. V5 remains at 21 operations. **One follow-up has only a partial V5 fit:** showing the preparation materials maps to `/open`, while creating the newly requested multilingual matrix still needs its substantive authoring brief.

## What this changes in the study

Identical control requests do not guarantee identical results. One request to execute a repair receives only a plan. Closeout requests receive interim commentary, blocked publication, a durable handoff or a claimed terminal receipt depending on source state. Archival eligibility questions do not authorize checkout deletion or establish project completion. A repeated continue retains its referent, ownership and prerequisites; it does not reset budgets or supersede newer published work.

Several rhetorical inputs demand a correction to execution rather than a literal explanation. An explicit time warning supplies a new deadline constraint, and a Finder-only instruction narrows computer control. These payloads cannot be discarded just because the broad operation already has a slash name. Explicit approval can confirm an authorized write while the harness or authentication still prevents it.

The preparation request also supplies a new creative task after an opener that only asked for ingestion. `/open` covers the display component. Calling the whole input `/explain` would change an imperative authoring request into a question; calling it a bare continuation would erase the new brief. This is recorded as partial coverage, not quietly counted as a successful substitution or resolved by inventing a new operation.

## Reply order and provenance

[The reply-order investigation](reply-order-findings-v1.md) confirms **29 invalid earlier-reply associations across 28 positions in 19 columns**. Every affected reply precedes its assigned input in both native ordinal and timestamp despite a matching turn ID. The current projector groups by turn without that order constraint. None affects an all-true-retention column.

This tranche contains one affected position: N03.2 at source line 2687. Its previously attached reply at line 2684 is not treated as its outcome; the actual later reply at 2690 remains. The original capture is preserved, and the exclusion is explicit in JSON. The broader capture/catalog has not been regenerated or claimed repaired. Forward order alone still does not prove unique causal association.

The nine sequences contain five inferred reply phases, two positions with no captured reply and seven shared-turn positions. The latter include three preparation inputs sharing one result, so they cannot be counted as three observed successful deliveries. One opener is a native shell command/result envelope; its embedded output is evidence, not another operator instruction. Two other openers carry inherited implementation plans. Derived context frames remain separately retained and are not counted as fresh operator prompts.
