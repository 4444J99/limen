# Authoring requests and task boundaries

Owner: [#3056](https://github.com/4444J99/limen/issues/3056). Publication: [draft #3087](https://github.com/4444J99/limen/pull/3087).

This review reads **nine retained native file views, containing 36 source positions**. Four positions contain only plugin recommendations, instructions and environment context; nine are each view's first task-bearing input; 23 follow those first task-bearing inputs. These are source-position categories, not 23 new independent human intentions or proof of complete logical sessions. Earlier case overlap and unknown emitter provenance remain explicit.

All 36 input bodies and their captured replies match unchanged native snapshots. The sequential reads covered 59,043,316 decoded bytes, with a 32 MiB per-source bound and stable before/after metadata. Nine bodies have explicit complete-retention flags, two are explicitly incomplete and 25 have no retention value. [Ordered cases and evidence](authoring-boundary-review-v1.json) retain those distinctions.

## The proposed vocabulary change

[V6 proposes `/compose`](vocabulary-v6.md) for authoring a requested content artifact from a bound brief. It preserves the required format, output maturity, destination, quantity, style reference, factual limits and acceptance evidence. N07.2's new naming matrix and A06.3's new editorial options brief are the two post-first supporting positions. N07.2 is a previously reviewed anchor, not an additional newly discovered case.

Three PDF requests provide initial-task controls. Each follows a complete operating preface, so none supplies an independent post-first case. The two handoff requests remain `/status + /handoff`; exact-head auditing remains `/review + /verify`; the late artifact-selection corrections remain `/correct + /open`. The new term is not used to collapse every kind of output into generic authoring.

## What `/compose` preserves

The naming-matrix input asks for a new exploratory artifact plus display. An operation name cannot recover its language set, single-word format, audience or review-only nature; the actual brief must remain attached. Under V6 its authoring component is a `/compose` candidate and its display component remains `/open`. Its V5 partial-fit record is preserved unchanged as historical analysis.

The editorial input asks for thirty days with at least five alternatives per day, each following its own coherent narrative. The assistant responds with a proposed plan for fifteen arcs and a future 450-option map. Fifteen is the assistant's design choice; it is not a new operator-selected minimum. The reply does not deliver every requested day-by-day option. Calling this merely an execution plan would lose the requested creative deliverable and blur a real stage mismatch.

The PDF controls similarly require an actual one-page, resume-matched artifact with bounded claims and requested rendering checks. The historical replies claim creation and visual verification; this study has not opened those PDFs. A safe-to-send label is neither a fresh sending instruction nor an observed send. Shared source previews and operating prefaces do not become extra independent requests.

## Context classification and source identity

A strict retained-text scan found **24 complete three-block operating prefaces** in the existing comparison. Four were rechecked against original native records in this tranche. Their known blocks end with no additional request text. A preface followed by real task text remains mixed and must be preserved; an occurrence inside a quoted request is not a context-only record. These analysis boundary checks are not production-projector tests or proof of emitter identity.

The active projector does not recognize this combined plugin-first preface and counts it among primary user-role inputs. That creates a false post-first boundary and shares a later task reply with a context item. The raw capture is retained. The owning repair must preserve pure context separately and keep task text when a record is mixed; it cannot broadly discard every matching prefix. Original-file validation for the other twenty census entries and admitted projector regression tests remain open.

[Source-key namespaces](source-key-namespace-v1.md) are also now explicit. This review uses the native-header-plus-snapshot namespace already used by the storage-view graph. Two earlier reports used captured-path fingerprints in their `column` fields. Their original values remain intact, with a checked crosswalk rather than a silent identity substitution. Header identity alone is insufficient to concatenate histories.

The structured scope answer A08.11 is bound to its actual native question call at source line 2364 and answer at 2377: call identity, question index, title and selected offered option all match. That identity check does not establish current skill installation or consumer use.

## Acceptance boundaries

The first 21 V5 contracts and frozen V2 evaluation stay unchanged. V6 adds one same-coder authoring proposal; no command is installed, no runtime substitution is executed, and independent validation is unproved. The existing HTML catalog still embeds V5. The new proposal and this comparison are reviewable alongside it; no regenerated-catalog claim is made.

All source positions, operations, counts, original retention values, preface/task boundaries, source-key crosswalk entries and local links are checked. Historical completion claims, source attachments, current external state, complete native ancestry and full corpus acceptance remain outside these checks. The existing reply-order repair and execution-admission requirements remain with the study owner. The goal stays active.
