## What the comparison establishes

Repeated words often select the same operation, but the complete intended
result depends on the target, current stage, payload, authority and acceptance.
A command must retain all six parts. Matching a verb is insufficient.

- **Proceed versus continue:** initial assent can select a prepared plan;
  later continuation advances it. Neither silently creates a budget or exception.
  C02/C04 preserve exhausted-budget constraints despite completion pressure.
- **Exceptions have their own binding:** B04, C03, C06 and D06 distinguish
  explicit time/path/host allowances from continuation. Broad override language
  remains provisional where its executable scope is not established.
- **Rhetorical corrections are operational input:** B05, B09, C03, C07 and
  D15 correct scope, process or cost. Replacing them with explain alone loses
  the demand to repair execution and reach the original endpoint.
- **New payloads survive compression:** D16 repeatedly says keep building,
  but each message names a different feature or integration slice. A bare
  continue would erase those requirements.
- **Evidence is not authority:** pasted reports, quoted permission questions
  and voice transcript context cannot approve actions. B06 and D11 distinguish
  preparation of a peer response from sending or performing its instructions.
- **One operation can have different legitimate results:** closeout can fail
  or pass as evidence changes; verification can expose an undeployed update;
  continue in an active planning mode can produce a plan. Equal operation
  does not establish equal external outcome.
- **Some prompts need a composition:** D12's request to show working outputs
  requires identifying/verifying them and displaying the resulting exact set.
  An existing-artifact open command alone does not perform that inventory.
- **Some cases remain unresolved:** an empty request with an external log,
  an unread full attachment, or unbound exception intent cannot receive a
  successful reduction merely because an assistant later acted.

## Coverage and verification limits

Every included source reports EOF, zero recorded extraction gaps and unambiguous
stored order. Every included retained body is marked complete with no recorded
media/extra-part gap. That does **not** prove the whole original logical session
is present. Compactions, frame inputs, possible ancestors, external references,
attachments and side histories remain separate provenance questions.

The three short attachments for B06.1, C06.1 and D11.1 were read in place.
D06.1, D08.4 and D16.18 reference available longer attachments that were not fully
read in this tranche. Other Page, file and export references were not exhaustively
resolved. Their contents are not invented or credited as reviewed.
B02's opener and C07.4 have no captured final; later replies do not fill those gaps.
D15 contains seven voice inputs; repeated transcript text is not seven new copies
of each earlier instruction. Ambient UI state and managed goal frames remain
separate from the 254 retained prompt positions.

Verification checks source keys, every ordered source line, per-sequence case
counts, contiguous positions, known v5 operation names, response-attribution
labels and whole-report readback. This is a documentation/data verification
batch; it does not run historical external actions, validate installed commands,
rerun the blocked full renderer, or replace independent substitution testing.

Result: all 36 source bindings and all 218 contiguous case positions passed.
All operation names exist in v5. Attribution checks preserved 31 shared-reply
positions, two missing finals and seven voice inputs. Complete text readback
matched both intended artifacts in bounded sections. Whitespace checks passed.

The full original study remains active. Keep this cohort separate from earlier
denominators until logical lineage and duplicated history are reconciled.
