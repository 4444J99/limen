# Completion and switch predicates

`python3 .../check.py` verifies capsule integrity, the exact bypass-all launch contract, finite
runway, and a clean owned tree. `bash .../launch.sh --check` exercises that predicate without
registering, admitting, or launching. Neither is an implementation or estate-completion predicate.

For implementation, run the implicated registered verification once per exact tree and record
repository-qualified publication, CI, deployment, and runtime receipts. Preserve unchanged green
shards. A machine-wide host-admission denial is a blocker, not a pass. Do not suppress failures or
delete preserved branches to manufacture closure.

At packet boundaries, re-check the canonical deadline and live resources. If work cannot finish
within remaining runway, stop new execution, publish the exact outcome to its durable owner, and
emit a bounded successor. Never renew runway silently, spawn unreserved children, or restart a
running command merely because observation timed out.

The normal closure predicates retain their authority:

```bash
scripts/no-tasks-on-me.sh
scripts/credential-wall.py --check
```

Do not claim zero dangling items, merge, deployment, runtime adoption, or estate green without the
corresponding positive receipts.
