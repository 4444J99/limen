# Completion and switch predicates

`python3 .../check.py` verifies only capsule integrity, finite runway and a clean owned tree.
`bash .../launch.sh --check` validates the launch path without launching an agent. These are
handoff checks, never estate-completion predicates.

For the implementation lane, run the implicated registered verification once per exact tree,
then record repository-qualified publication, CI and runtime receipts. Preserve valid unchanged
shards. `scripts/no-tasks-on-me.sh` and `scripts/credential-wall.py --check` retain their normal
closure authority: do not suppress failures or delete preserved branches to manufacture success.

Current strict-closeout exception is owned by Limen #2664: the global predicate reports retained
landed branches, while the user explicitly requires preservation. It also treats a published
squash-merged branch as unpushed when its tracking target is main. Verify landing/custody before
any authorized disposition; correct evidence classification without weakening preservation.
The empty merge-policy-denial worktree has no unique code; its deferred intent is owned by #2664.

At packet boundaries check the canonical contract deadline and live resources. If work cannot
finish within remaining runway, stop new execution, publish the exact outcome to its owner, and
create a bounded successor. Never renew runway silently, spawn unreserved children, or restart
a running command because observation timed out. No final completion percentage is authorized.
